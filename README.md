# 中文漫畫書目查詢

現場人員輸入書名、作者、出版社或 ISBN，查出 ISBN 後複製到店內查詢系統使用。

## 檔案說明

| 檔案 | 作用 |
|---|---|
| `app.py` | 網頁畫面（查詢頁＋資料維護頁） |
| `db.py` | 所有資料庫操作：建表、查詢、寫入、ISBN 整理 |
| `importer.py` | 讀出版社建檔檔案、自動對應欄位 |
| `books.db` | **資料庫本體**，所有書目都在這一個檔案裡 |
| `requirements.txt` | 告訴 Streamlit Cloud 要安裝哪些套件 |

⚠️ 五個檔案都要放在 GitHub 儲存庫的**最外層**，不能放進資料夾。

---

## SQLite 是什麼？

SQLite 是一種「裝在單一檔案裡的資料庫」。可以把 `books.db` 想成一個特別的 Excel 檔：

- 裡面有一張表 `books`，欄位是 ISBN、書名、作者、出版社。
- 跟 Excel 不同的是，它不需要整個打開才能查，程式可以直接從幾十萬筆裡快速找出符合的幾筆。
- 不用架伺服器、不用付費、不用帳號，檔案在哪裡資料庫就在哪裡。

這個專案裡，你**不需要寫任何 SQL 指令**，新增資料都透過網頁的「資料維護」頁完成。

### 想直接打開 books.db 看內容？

安裝免費軟體 **DB Browser for SQLite**（https://sqlitebrowser.org），用它開啟 `books.db`：

- 「瀏覽資料」分頁：像 Excel 一樣看所有書目，也可以直接改錯字或刪除某筆。
- 改完記得按「寫入變更」，再把檔案上傳到 GitHub。
- `search_key` 欄位是給查詢用的，不用理它，網站啟動時會自動重算。
- 不要改表格結構（新增或刪除欄位）。

## 第一次部署

1. 在 GitHub 建立新的儲存庫（例如 `manga-search`），把五個檔案上傳到最外層。
2. 到 Streamlit Community Cloud 按「Create app」，選這個儲存庫，主程式選 `app.py`。
3. 部署完成後會得到一個網址，分享給各店使用。

這個工具不需要 Google 登入，也不需要設定 Secrets。

## 日常更新流程（新增出版社建檔資料）

1. 打開網頁，左側選「🛠 資料維護」。
2. 上傳出版社寄來的 Excel 或 CSV。
   - 系統會自動找表頭那一列、自動對應欄位；不對的話用下拉選單改。
   - 檔案裡沒有出版社欄位時，填入出版社名稱即可。
   - ISBN 有連字號、是 10 碼、或被 Excel 存成數字都沒關係，會自動整理成 13 碼。
3. 看一下預覽和「略過的資料」，沒問題就按「併入資料庫」。
4. 有好幾個檔案就重複 2～3。
5. 按「下載 books.db」。
6. 到 GitHub 儲存庫 → Add file → Upload files → 上傳剛下載的 `books.db` → Commit。
   網站一兩分鐘內會自動更新。

### 重複的書怎麼辦？

同一個 ISBN 只會有一筆。再次匯入時會更新書名、作者、出版社；新檔案某欄空白的話，會保留原本的資料，不會被清掉。

### 為什麼不直接在網頁上存檔？

Streamlit Cloud 的主機會定期重啟，重啟後網頁上寫入的資料會消失，只有 GitHub 上的檔案是永久的。所以流程設計成「網頁整理 → 下載 → 上傳 GitHub」。

## 容量參考

每筆書目約佔 0.2～0.3 KB，十萬筆約 25 MB。

- GitHub 網頁上傳單檔上限 25 MB，超過後改用 **GitHub Desktop**（免費）上傳即可，上限是 100 MB。
- 資料維護頁在檔案超過 20 MB 時會提醒。

## 常見欄位名稱不被自動辨識？

打開 `importer.py`，在最上方 `COLUMN_ALIASES` 對應的清單裡加上新名稱，例如出版社把書名欄叫「商品中文名稱」，就加到 `"title"` 那一行。
