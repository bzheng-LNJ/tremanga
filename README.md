# 中文書籍查詢系統

現場人員輸入書名、作者、出版社或 ISBN，查出 ISBN 後複製到店內查詢系統使用。

## 商品種類

查詢頁上方可以切換四個種類，每個種類各自一個資料庫檔，查詢時不會混在一起：

| 種類 | 資料庫檔 | 欄位 |
|---|---|---|
| 中文書 | `books.db` | ISBN、書名、作者、定價、出版社 |
| JUMP SHOP | `jumpshop.db` | JAN、商品名稱、店頭賣價 |
| 文具 | `stationery.db` | JAN、商品名稱、售價（暫定） |
| 周邊 | `goods.db` | JAN、商品名稱、售價（暫定） |

還沒有資料的種類不用先準備 .db 檔，第一次發佈時會自動建立。

## 檔案說明

| 檔案 | 作用 |
|---|---|
| `app.py` | 網頁畫面（查詢頁＋資料維護頁） |
| `config.py` | **商品種類與欄位設定**，要新增種類、改欄位都改這裡 |
| `db.py` | 所有資料庫操作：建表、查詢、寫入、ISBN／JAN 整理 |
| `importer.py` | 讀建檔檔案、自動對應欄位 |
| `github_store.py` | 發佈時直接把 .db 寫回 GitHub |
| `*.db` | 各種類的資料庫本體 |
| `requirements.txt` | 告訴 Streamlit Cloud 要安裝哪些套件 |

⚠️ 所有檔案都要放在 GitHub 儲存庫的**最外層**，不能放進資料夾。

---|---|

## SQLite 是什麼？

SQLite 是一種「裝在單一檔案裡的資料庫」。可以把每個 .db 檔想成一個特別的 Excel 檔：

- 每個 .db 檔裡有一張表（中文書叫 `books`，其他叫 `items`），欄位就是上面表格列的那些。
- 跟 Excel 不同的是，它不需要整個打開才能查，程式可以直接從幾十萬筆裡快速找出符合的幾筆。
- 不用架伺服器、不用付費、不用帳號，檔案在哪裡資料庫就在哪裡。

這個專案裡，你**不需要寫任何 SQL 指令**，新增資料都透過網頁的「資料維護」頁完成。

### 想直接打開 books.db 看內容？

安裝免費軟體 **DB Browser for SQLite**（https://sqlitebrowser.org），用它開啟想看的 .db 檔：

- 「瀏覽資料」分頁：像 Excel 一樣看所有書目，也可以直接改錯字或刪除某筆。
- 改完記得按「寫入變更」，再把檔案上傳到 GitHub。
- `search_key` 欄位是給查詢用的，不用理它，網站啟動時會自動重算。
- 不要改表格結構（新增或刪除欄位）。

## 第一次部署

1. 在 GitHub 建立儲存庫，把所有檔案上傳到最外層。
2. 到 Streamlit Community Cloud 按「Create app」，選這個儲存庫，主程式選 `app.py`。
3. 完成下面的「發佈設定」。

## 發佈設定（讓各組直接登錄，不用碰 GitHub）

### 1. 產生 GitHub 權杖

GitHub 右上角頭像 → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token：

- Repository access：選 **Only select repositories**，只勾這個查詢系統的儲存庫
- Permissions → Repository permissions → **Contents：Read and write**（其他都不用開）
- 有效期限依公司規定設定，到期前記得更新

產生後複製那串 `github_pat_...`（只會顯示一次）。

### 2. 設定 Streamlit Secrets

Streamlit Cloud 的 app 頁面 → Settings → Secrets，貼上：

```toml
[github]
token  = "github_pat_貼上剛才的權杖"
repo   = "你的帳號/儲存庫名稱"
branch = "main"

[editors]
小鄭   = "自訂密碼1"
文具組 = "自訂密碼2"
漫畫組 = "自訂密碼3"
```

`[editors]` 裡每一行是一個登錄者：左邊是名稱（會記在登錄紀錄裡），右邊是密碼。密碼不要重複。要新增或停用某個組別，改這裡就好。

⚠️ 權杖和密碼只能放在 Secrets，絕對不要寫進儲存庫的任何檔案。

## 日常登錄流程

1. 打開網頁，左側選「🛠 資料維護」，輸入密碼登入。
2. 選商品種類，上傳建檔檔案（Excel 或 CSV）。
   - 系統會自動找表頭那一列、自動對應欄位；不對的話用下拉選單改。
   - 檔案裡沒有出版社欄位時，填入出版社名稱即可。
   - 中文書的建檔檔案如果集數另外一欄，指定「集數」後會自動接在書名後面（「航海王」＋「05」→「航海王 5」）；書名已經含集數的檔案不用指定。
   - ISBN 有連字號、是 10 碼、或被 Excel 存成數字都沒關係，會自動整理成 13 碼。
   - JAN 開頭的 0 被 Excel 吃掉（變成 12 碼）時會自動補回。
   - 價格寫成「NT$1,200元」「¥1,200」之類也會自動整理成「1200」。
3. 看預覽和「略過的資料」，沒問題就按「發佈」。查詢頁馬上就查得到。

頁面下方有該種類最近的登錄紀錄（誰、什麼時候、哪個檔案、新增幾筆）。

### 多人同時登錄會不會互相蓋掉？

不會。發佈的瞬間程式才去 GitHub 抓最新版本合併；如果剛好有人先發佈，程式會自動重抓再合併一次。

### 發佈後網站重新整理了？

GitHub 上的檔案更新後，Streamlit 有時會重新載入網站，正在操作的人可能需要重新登入，資料不受影響。

### 重複的書怎麼辦？

同一個 ISBN／JAN 只會有一筆。再次匯入時會更新其他欄位；新檔案某欄空白的話，會保留原本的資料，不會被清掉。

## 容量參考

每筆書目約佔 0.2～0.3 KB，十萬筆約 25 MB。

- GitHub 單檔上限 100 MB，以目前的資料量還很遠。

## 修改設定（config.py）

**欄位名稱不被自動辨識**：在該欄位的 `aliases` 清單加上新名稱。例如 JUMP SHOP 的檔案把價格欄叫「販売価格」，就加到 JUMP SHOP 的 `price` 那一行。

**文具／周邊要加欄位**（例如品牌、系列）：在該種類的 `fields` 裡照格式加一行，例如
`{"key": "brand", "label": "品牌", "kind": "text", "aliases": ["品牌", "廠牌", "メーカー"]},`
舊的 .db 會在網站啟動時自動補上新欄位，不用重建。

**新增一個種類**：複製一整段設定、換一個名字和 .db 檔名即可。
